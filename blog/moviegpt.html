How I Built MovieGPT: From a Netflix Dataset to a Local AI Assistant

I wanted to understand what actually happens between a user's question and an AI-powered recommendation. MovieGPT became my small laboratory for that.

My starting point was not a large language model. It was a CSV file containing Netflix titles. The dataset has thousands of movies and TV shows with fields such as title, cast, country, genres, release year, and description.

1. Clean the data first

Before building anything intelligent, I had to make the data usable. I removed fields that were not useful for the recommendation task, filled missing values with a controlled unknown value, and extracted useful information such as movie duration and number of seasons.

2. Turn descriptions into something a computer can compare

The important idea was to combine several text fields into one feature string: title, director, cast, country, categories, and description. I then used TF-IDF to convert those words into numerical vectors.

This gives every title a position in a high-dimensional text space. Titles with similar language tend to end up closer together.

3. Find the nearest titles

For recommendations I used scikit-learn's NearestNeighbors with cosine distance. When a user selects a title, the system finds nearby vectors and returns the closest matching titles.

4. Where Qwen fits

I wanted the application to feel like an assistant instead of a search box. Qwen 2.5 3B runs locally through Ollama and handles the conversational layer: it identifies whether the user is greeting the assistant, asking for recommendations, requesting help, or saying goodbye.

Qwen does not invent the recommendations. A deterministic title-matching function identifies the movie or show in the user's message, and the recommendation engine makes the actual selection.

Architecture: User → Tkinter → Qwen → intent detection → title matching → TF-IDF + Nearest Neighbors → recommendations.

5. What I learned

The biggest lesson was that an AI application does not need to put an LLM in charge of everything. Classical machine learning can be excellent at a focused job, while an LLM can make the interface more natural.

MovieGPT is still a learning project, but it gave me a clearer picture of how data preparation, machine learning, local inference, and application code can work together.
